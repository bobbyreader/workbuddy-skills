# 共享融合月报取数源分析 — 使用场景与工作流程

> 本文档定义了本 Skill 的两大核心使用场景及对应的标准化工作流程。
> ⚠️ 注意：不同单位的报表数据不同，核心是掌握公式逻辑和表间关系，不带入具体数值。

---

## 场景一：单格取数源追溯

### 触发条件
用户询问某张报表的某个单元格数据不对，需要追溯其数据来源。

### 工作流程

```
用户提问：「XX表的YY项目ZZ列的数据看起来不对，帮我查一下」
    ↓
Step 1: 定位目标单元格
    ↓
Step 2: 读取该单元格的批注 (cell.comment.text)
    ↓
Step 3: 判断公式类型
    ├── 运算公式 → Step 4A: 拆解引用链
    └── 取数公式 → Step 4B: 分析取数来源
    ↓
Step 4A: 运算公式拆解
    │   解析 .(行项目, 字段) 引用的所有上游格子
    │   逐个检查上游格子的批注和数据
    │   直到追溯到最底层的「取数公式」为止
    │
    └── Step 4B: 取数公式来源分析
        ├── A. 历史报表引用 → 提示需核对历史报表数据
        ├── B. 中间表/跨表引用 → 提示需检查被引表的对应格子
        └── C. 账务取数 ⭐ → 
            ├─ 解析科目代码条件
            ├─ 到科目维度汇总表中查询匹配行的实际值
            └─ 对比报表值 vs 科目维度汇总表值
                ├─ 一致 → 问题在更上层（运算过程）
                └─ 不一致 → 账务本身有问题，需进行账务调整
    ↓
Step 5: 输出结论和建议
```

### 输出格式

```markdown
## 取数源分析结果

### 目标位置
- 报表：XXX
- 行项目：YYY (行次 N)
- 字段：ZZZ
- 当前值：XXXXX

### 公式信息
- **类型**: 运算公式 / 取数公式
- **原始批注**: [完整批注内容]

### 数据溯源链路
[从目标单元格到最底层源的完整链条]

### 结论
[明确指出问题出在哪一环]

### 建议
- 方案A: 修改 XX 表 XX 格子数据（如果源头数据有误）
- 方案B: 进行账务调整 — [具体调整方向]
- 方案C: 添加稽核说明（如果差异合理可接受）
```

## 场景二：批量稽核问题分析与整改

### 触发条件
用户完成单体表后执行批量稽核，稽核未通过，提供稽核提示信息，要求定位问题并给出整改建议。

### 稽核提示的结构理解

一个典型的稽核提示包含以下要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| **稽核类型** | 逻辑性稽核 / 勾稽关系稽核 / ... | `1、逻辑性稽核` |
| **稽核规则** | 被检查的表达式和约束条件 | `(经营活动现金流出小计_31,本期金额_3) >= 0` |
| **错误提示** | 系统给出的错误描述 | 必须！...应大于等于0... |
| **左表达式** | 实际计算出的报表值 | `(-3,405,671.80)` |
| **右表达式** | 规则要求的阈值/对照值 | `0` |
| **稽核结果** | 左 - 右的计算差值 | `-3,405,671.80` |
| **不通过原因** | 为什么没过 | 左表达式应>=右表达式 |

### 稽核规则分类

#### 类型1：逻辑性稽核
- 特征：检查单个值的合理性
- 示例：现金流出 >= 0（流出金额不应为负）、资产 >= 0 等
- 排查重点：被检查格子的取数来源是否正确

#### 类型2：勾稽关系稽核
- 特征：检查两个或多个格子之间的关系
- 示例：资产负债表平衡（资产=负债+权益）、表间勾稽（如利润表净利润→资产负债表未分配利润）
- 排查重点：参与运算的所有格子的取数来源

#### 类型3：表间一致性稽核
- 特征：同一指标在不同表中应该一致
- 示例：资产负债表的货币资金 = 现金流量表的期末现金及等价物
- 排查重点：两张表各自的取数来源对比

### 工作流程

```
用户提供稽核提示截图/文本
    ↓
Step 1: 解析稽核提示
    ├─ 提取：被检查的(报表/行项目/字段)
    ├─ 提取：稽核规则（>= / <= / = / 勾稽关系等）
    ├─ 提取：左表达式实际值、右表达式预期值
    └─ 明确：差值是多少，方向如何
    ↓
Step 2: 定位被检查的单元格
    ├─ 根据行项目名 + 行次 + 字段名，精确定位到 Excel 中的坐标
    └─ 读取当前值，确认与稽核提示一致
    ↓
Step 3: 读取批注，追溯取数源（同场景一的 Step 2-4）
    ↓
Step 4: 结合稽核规则，分析根因
    ├─ 如果是逻辑性稽核 → 重点看被检查格子的直接取数源
    ├─ 如果是勾稽关系稽核 → 重点看参与勾稽的所有格子的取数源
    └─ 如果是表间稽核 → 对比两表的取数路径差异
    ↓
Step 5: 给出整改建议
```

### 整改建议的分类

| 建议类型 | 适用场景 | 操作方 |
|---------|---------|--------|
| **修改报表数据** | 取数源来自其他报表/中间表，且源数据有误 | 报表编制人 |
| **账务调整** | 取数源是账务取数，且科目维度汇总表中的数据有问题 | 财务人员做账务调整 |
| **添加说明** | 差异合理（如特殊业务导致），可通过写说明放行 | 报表编制人 |
| **检查合并范围** | 小合并/大合并时，下属单位数据漏报或多报 | 合并编制人 |

### 输出格式

```markdown
## 稽核问题分析报告

### 稽核基本信息
- **稽核类型**: 逻辑性稽核 / 勾稽关系稽核 / ...
- **被检查项**: {表名}.{行项目}({行次}), {字段}
- **稽核规则**: {表达式}
- **左表达式(实际)**: {值}
- **右表达式(预期)**: {值}
- **差值**: {值}
- **不通过原因**: {原因}

### 目标单元格定位
- **Sheet**: XXX
- **坐标**: XX{行号}
- **当前值**: XXXX
- **批注内容**: [完整批注]

### 取数源追溯
[完整的追溯链路图]

### 根因分析
[基于取数源的分析，找出导致不符合规则的真正原因]

### 整改建议
1. 【首选方案】{具体操作} — {理由}
2. 【备选方案】{具体操作} — {理由}
3. 【如无法修改】可考虑添加稽核说明：{建议措辞要点}
```

## 关键原则

1. **不带入具体数据值**：每次分析都基于用户提供的最新文件和稽核提示
2. **先追溯再建议**：必须看完完整的取数链路后再下结论
3. **区分"能改"和"不能改"**：账务取数的源头在账务系统中，不是报表能改的
4. **给用户选择权**：通常提供多个方案让用户根据实际情况选择
