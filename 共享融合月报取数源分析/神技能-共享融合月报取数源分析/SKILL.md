# 神技能-共享融合月报取数源分析

## Purpose

本 Skill 用于支持**共享融合系统**中**快报**的取数源分析工作，服务于每月底财务月结时的出表需求。核心能力是：通过解析报表 Excel 文件中的**单元格批注（Comment）**来追溯每个数据的来源，区分运算和取数两种逻辑，并将账务取数映射到科目维度汇总表中验证。

## Business Context

### 使用时机
- **时间节点**：每月底财务做月结时
- **系统来源**：共享融合系统 → 快报模块
- **目的**：完成月度报表出具工作

### 报表层级体系（三级）+ 公式体系差异

```

│    大合并 (Level 3) — 仅1家         │  编码1002，最终汇总层
│    ✅ 有账务取数（与单体表同体系）   │  全公司汇总后的科目维度汇总表
├─────────────────────────────────────┤

│   ❌ 正式报表无账务取数              │  取数来源：历史报表 + 运算汇总
```

## 核心知识：公式批注体系

> 详细说明见 `references/公式体系说明.md`

### 关键认知：数据藏在批注里

报表 Excel 文件中，每个有数据的单元格都可能带有**批注（Cell Comment）**。整个文件约 **18,569 个批注**，记录了每个格子的完整计算/取数逻辑。

**读取方式**（使用 openpyxl）：
```python
cell = ws.cell(row=row, column=col)
if cell.comment is not None:
    formula_text = cell.comment.text  # 批注内容就是取数/运算公式
```

### 两大公式类型

#### 类型1：运算公式（`运算公式1 :`）
- **含义**：内部汇总计算，不涉及外部取数
- **模式**：引用同表或其他表的已有格子进行加减乘除
- **典型场景**：小计、合计、增减额、增减率、比率指标

#### 类型2：取数公式（`取数公式1 :`）
- **含义**：从外部获取数据，分三种来源：
  - **A. 历史报表** → `去年.12.资产负债月报表.(货币资金元_2,期末数_5)` — 用于年初数、上年同期
  - **B. 中间表/其他报表** → `.资产负债表中间表（单体-重分类）.(元_2,重分类后金额_6)`
  - **C. 账务取数 ⭐** → `账务取数：本财务组织_本年_本月__01 中国大陆企业会计账簿_(科目代码条件)__本位币(人民币)__年借方发生额__合并数`

### 账务取数的完整格式解析

```
账务取数：{财务组织}_{期间}__{账簿类型}_({科目条件})_{币种}__{取值字段}__{合并标志}
```

| 组成部分 | 说明 | 示例 |
|---------|------|------|
| 财务组织 | 固定值 | 本财务组织 |
| 期间 | 年度+月份 | 本年_本月 / 本年_本年 |
| 账簿类型 | 编号+名称 | 01 中国大陆企业会计账簿 |
| 科目条件 | 科目代码或现金流量分类 | (1002 银行存款)+(1001 库存现金) |
| 币种 | 固定 | 本位币(人民币) |
| 取值字段 | ⭐关键字段 | 期初借方余额 / 期末借方余额 / 年借方发生额 等 |
| 合并标志 | 固定 | 合并数 |

### 取值字段 ↔ 科目维度汇总表映射

| 账务取数中的取值字段 | 对应科目维度汇总表列 |
|---------------------|-------------------|
| 期初借方余额 / 期初贷方余额 | 第7列：期初余额 |
| 期末借方余额 / 期末贷方余额 | 第13列：期末余额 |
| 年借方发生额 | 第10列：年借方累计 |
| 年贷方发生额 | 第11列：年贷方累计 |

> 完整映射规则见 `references/科目维度汇总表说明.md`

## Workflow — 两大核心使用场景

> 详细工作流见 `references/使用场景与工作流.md`

### 场景A：单格取数源追溯

**触发**：「XX表的YY项目数据不对，帮我查下源头」

```
定位目标 → 读批注 → 判断公式类型 → 追溯源头 → 给建议
                                    ├─ 运算公式→拆解上游格子
                                    └─ 取数公式→判断来源(A/B/C)
                                         C=账务取数→查科目维度汇总表→对比值
```

**输出**：完整的取数链路 + 问题根因 + 整改建议（改报表/调账务/写说明）

### 场景B：批量稽核问题分析与整改 ⭐

**触发**：单体表做完后批量稽核未通过，提供稽核提示截图/文本

**稽核提示结构**：
| 要素 | 说明 | 示例 |
|------|------|------|
| 稽核类型 | 逻辑性/勾稽关系/表间一致性 | `1、逻辑性稽核` |
| 稽核规则 | 表达式+约束 | `(经营活动现金流出小计_31,本期金额_3) >= 0` |
| 左表达式 | 实际报表值 | `(-3,405,671.80)` |
| 右表达式 | 预期阈值 | `0` |
| 不通过原因 | 差异说明 | 左应>=右 |

**分析步骤**：
1. 解析稽核提示 → 提取被检查项、规则、实际值、预期值
2. 定位被检查单元格 → 读取批注和当前值
3. 追溯取数源（同场景A）
4. 结合稽核规则分析根因
5. 给整改建议：修改报表 / 账务调整 / 添加说明

### 报表层级处理流程（背景框架）

#### 第一阶段：单体表分析（Level 1）
对单体单位执行场景A或B的分析工作

#### 第二阶段：小合并验证（Level 2）— 共8家单位
> 完整清单见 `references/8个小合并单位清单.md`

**公式体系特征（与单体表的关键区别）：**
- **正式报表无账务取数**：资产负债表、利润表、现金流量表、成本表的取数公式全部为「去年历史引用」或「运算汇总」，**不查SAP，不查科目维度汇总表**
- **数据来源路径**：下级单体表单位的报表 → 汇总叠加 + 合并抵销 → 生成合并报表
- **中间表残留账务取数批注**：`资产负债表中间表(单体-重分类)` 中仍有105个账务取数批注（格式与单体表相同），但这可能是模板残留或仅用于核对，**正式出表不依赖它**

**分析策略：**
- 数据问题应追溯到**下属单体表单位**的报表
- 重点检查合并抵销的完整性
- 如需追溯具体数值来源，需查看对应下级单体表的批注

#### 第三阶段：大合并审核（Level 3）— 仅1家单位
> 详细说明见 `references/大合并单位说明.md`

| 属性 | 值 |
|------|-----|
| 编码 | 1002 |
| 名称 | 国家电投集团湖北电力有限公司（合并） |
| 数量 | 全公司唯一 |
| 公式体系 | **✅ 与单体表一致，有完整账务取数** |

**⚠️ 重要修正**：大合并不是像小合并那样"无账务取数"。经实际分析其报表集（18,569条批注），大合并的正式报表中：
- ✅ 现金流量月报表：**46个**账务取数
- ✅ 成本情况月报表：**139个**账务取数
- ✅ 利润月报表(三)：**300个**账务取数
- 资产负债月报表：通过中间表间接取数（与单体表一致）

**大合并与单体表的差异仅在数据范围**：大合并的科目维度汇总表中包含的是**全公司所有下级单位汇总后的账务数据**，而非单个单位的。

**分析策略**：
- **可使用本Skill全部能力**：批注解析、账务取数追溯、科目维度汇总表查询均适用
- 如数值异常，需判断是全公司汇总问题还是某个下级源头的问题
- 可逐层向下定位：大合并 → 小合并 → 具体单体表单位
